# Release bundle size plan

Measured on 2026-10-31 at commit 07e4e8d (kit version 2026-10-31.16). This is a proposal only: it removes, moves
or rewrites no shipped file. Every number below was measured with the command shown, except where a row says
"inferred".

**Status (2026-11-01, kit 2026-11-01.1): steps 1 and 2 are done** (the owner's decision). `tools/release_bundle.py`
holds the one exclusion list (`EXCLUDED`: `dist/`, `.claude/`, `mods/<name>/tests/`) and `EVIDENCE_FILES`, which
`tools/make-bundle.sh` imports and `check-release` reads. The three rescore files ship as
`claude-usage-optimizer-evidence.sh`, an extra file of the same artifact, published next to the bundle; it extracts
and verifies only. Steps 3 and 4 and the other section 9 questions stay open.

## 1. Where the bundle stands

`bash tools/make-bundle.sh` wrote `dist/claude-usage-optimizer-bundle.sh` with 634 files and 15,618,322 bytes.
After `python3 -I tools/make-page.py`, `python3 -I tools/check-release.py` exited 0 with `Summary: 0 FAIL, 2 WARN`:
the `bundle` check warns on size and `patterns` warns because this machine has no local patterns file.

| Measure | Bytes |
| --- | ---: |
| Limit (`--max-bytes` default, `tools/check-release.py`) | 16,000,000 |
| Bundle | 15,618,322 |
| Headroom | 381,678 (2.4% of the limit) |
| WARN threshold (`size > max_bytes * 0.94`, `tools/check-release.py:118`) | 15,040,000 |
| Shipped bytes (sum of `git ls-files` sizes) | 15,338,279 |
| Bundle overhead over shipped bytes | 280,043 |

The bundle compresses nothing. `tools/make-bundle.sh` writes each tracked and untracked, non-ignored file (except
`dist/`) as a raw `cat > ... <<'__USAGE_OPTIMIZER_EOF__'` heredoc, and lists each file's sha256 twice: once in the
header comment and once in a `verify_sha256` line. That costs about 476 bytes per file on top of its contents, so
many small files cost more than their size suggests (the 419 files under `skills/` carry 199,661 bytes of it).

The warning starts at 94% of the limit, not at 97%: the code warns within 6%, so every release since the bundle
passed 15.04 MB has warned. IMPROVING.md section 8 still says the bundle is 13.9 MB with 2.1 MB of headroom; that
line is stale.

This plan ships too, because `findings/` is installed: about 15 KB of contents plus about 476 bytes of bundle
overhead come off the headroom at the next build. The numbers in this plan were measured before it was added.

## 7. Not proposed: compressing the bundle

A gzip payload would cut the whole kit to about 2.3 MB of tar.gz, roughly 3.0 MB once base64-encoded (inferred).
It is not proposed here: the bundle is plain text so it can be read before it runs and published as
`text/plain`; `tools/release_bundle.py`, `tools/diff-bundle.py` and the `fresh` check all parse its heredocs; and
extraction would start depending on `tar`, `gzip` and `base64` on every target. It is the owner's call if the moves
above are rejected.

## 8. Projected headroom and order

Every step's exclusion must be applied in the two places that list shipped files, `tools/make-bundle.sh:65-67`
and `shipped_files` in `tools/release_bundle.py:29`, or the `fresh` check fails. The best form is one shared
exclusion list both read. Each step is its own release, rebuilt and checked with `tools/check-release.py`.

| Step | Item | Bundle bytes saved | Bundle after | Headroom after |
| ---: | --- | ---: | ---: | ---: |
| 0 | Today | | 15,618,322 | 381,678 |
| 1 | Shared exclusion list; leave `.claude/` out | 34,074 | 15,584,248 | 415,752 |
| 2 | Move the three rescore files to the evidence file; update the manifest and FINDINGS.md pointers | 4,896,097 | 10,688,151 | 5,311,849 |
| 3 | Prove `lane-bench panels --outcomes` reproduces `panels.json` byte for byte in a temp folder, then leave it out and add a warn-only install step that rebuilds it | 2,739,450 | 7,948,701 | 8,051,299 |
| 4 | Move the knowledge pack; make install accept an empty `skills/`; ship the pack as its own file with its own install step | 2,402,197 | 5,546,504 | 10,453,496 |

The order runs from least to most risk. Step 1 builds the exclusion mechanism on files nothing installs. Step 2
is the biggest saving for no code change at install. Step 3 adds an install step and needs a proof first. Step 4
changes the installer and the knowledge pack's release flow. If every step is accepted the bundle drops to about
5.55 MB, leaving about 10.45 MB (65% of the limit), before the few hundred bytes of new install code. Steps 1 and 2
alone leave 5.31 MB.
